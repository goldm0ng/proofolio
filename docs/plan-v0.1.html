취준 OS 기획안

공고 관리부터 학습, 이력서, 면접, 그리고 채용담당자에게 보여줄 공개 프로필까지. 노션과 문서 사이를 오가지 않고 한 곳에서 취업 준비 전체를 처리하는 개인 커리어 운영체제.

0. 총평

기획에 대한 판단

방향은 맞습니다. 다만 정체성을 바꿔야 합니다. 지금 기획은 "기능 6개가 모인 사이트"인데, 이 서비스의 본질은 내 취업 컨텍스트를 한 곳에 쌓는 저장소 하나와 그 저장소를 읽고 다시 채우는 뷰 여러 개입니다. 이렇게 정의해야 기능들 사이에 데이터가 흐르고, "책임 분리와 응집도"라는 말이 구호가 아니라 설계가 됩니다.

두 번째 메시지에서 말한 "링크 하나로 나를 보여주는 증빙 자료"는 부가 기능이 아니라 이 제품의 두 번째 얼굴입니다. 같은 데이터가 안쪽에서는 작업 공간이고, 바깥쪽에서는 증빙이 붙은 이력서가 됩니다. 이를 위해 모든 데이터에 처음부터 공개/비공개 구분을 둡니다.

잘 잡은 것

  • 문제가 실제이고 사용자가 본인. 검증 비용이 0에 가깝고, 매일 쓰면서 고칠 수 있습니다.
  • 컨텍스트 집중. 프로젝트·경험·지원 이력이 한 곳에 있으면 AI 산출물 품질이 근본적으로 달라집니다. 지금은 매번 노션에서 복사해 붙여야 합니다.
  • 프로젝트 자체가 포트폴리오. LLM 스트리밍, 버전관리 모델, 외부 API 연동, 권한 분리, 스케줄러가 전부 들어가는 백엔드 소재입니다.

바로잡을 것

  • 스코프. 공채 시즌에 6개 모듈을 동시에 만들면 전부 미완성으로 끝납니다. 수직 슬라이스로 단계화하고 노션을 잠시 병행합니다.
  • "지원하자 한마디로 완성"은 목표가 아니라 방향. 자소서는 근거 기반 초안까지만 자동이고, 최종 문장은 사람이 씁니다. 완전 자동은 획일적 문장과 기업 AI 필터 리스크를 부릅니다.
  • 노션이 이미 잘하는 걸 다시 만드는 비용. 공고 관리는 임포트로 흡수하고, 초기 2주는 노션과 병행해서 데이터 유실을 막습니다.
한 문장 정의

내 프로젝트·경험·학습·지원 기록을 한 저장소에 쌓고, 그 위에서 지원서 초안·학습 퀴즈·모의면접을 돌리며, 바깥으로는 증빙이 붙은 공개 프로필을 내보내는 개인 커리어 OS.

1. 제품 정의

사용자 · 얼굴 · 원칙

사용자

  • 1차 사용자: 본인. 매일 로그인해서 공고를 정리하고, 학습하고, 지원서를 쓰고, 면접을 연습합니다.
  • 2차 사용자: 채용담당자·면접관. 자소서의 링크란이나 이력서 하단의 URL을 열어 프로젝트, 글, 자격증, 활동 데이터를 훑습니다. 로그인 없음, 읽기 전용, 빠른 로딩.

두 개의 얼굴

얼굴대상보이는 것절대 보이면 안 되는 것
워크스페이스본인전부-
공개 프로필채용담당자, 지인공개로 표시한 프로젝트·노트·자격증·활동 통계·현재 이력서지원 현황, 기업 분석, 면접 기록, 자소서 초안, 코테 실패 로그, 개인 연락처 외 개인정보

설계 원칙

  1. 한 번 적은 것은 다시 적지 않는다. 프로젝트에서 뽑은 경험이 이력서 블록, 자소서 근거, 면접 답변으로 재사용됩니다. 원본을 고치면 파생물에 반영 여부를 묻습니다.
  2. AI 산출물은 항상 초안 상태로 태어난다. 사람이 확인해서 확정하기 전까지는 어디에도 제출되지 않고 공개되지 않습니다.
  3. 기본값은 비공개. 모든 엔티티에 공개 범위 필드가 있고, 공개는 항목 단위로 명시적으로 켭니다.
  4. 학습 엔진은 하나. CS 퀴즈, 자격증 문제, 코테 재풀이, 스피킹 연습이 모두 같은 "문제 생성 → 시도 → 채점 → 재복습" 파이프라인을 씁니다. 모듈마다 엔진을 따로 만들지 않습니다.
  5. 취준이 먼저. 개발은 주 10시간 이내, 각 단계는 끝나는 즉시 실사용 가능한 상태여야 합니다.

3. 모듈별 기획

각 모듈은 목적 · 유저 스토리 · 핵심 기능 · 데이터 · AI · MVP 경계 · 리스크로 정리
M0

지원 파이프라인

Phase 0노션 대체
목적

공고 발견부터 최종 결과까지 상태를 한눈에 보고, 마감을 놓치지 않고, 지원마다 무엇이 필요한지 체크한다. 지금 노션에서 수기로 하는 일을 그대로 흡수하되 입력을 자동화한다.

유저 스토리
  • 공고 URL이나 본문을 붙여넣으면 회사·직무·마감·전형 절차·필요 서류·자소서 문항이 추출되어 카드가 생긴다.
  • 칸반에서 카드를 옮긴다. 관심 → 지원 예정 → 작성 중 → 제출 → 서류 통과 → 필기·코테 → 면접 → 최종. 결과와 회고를 남긴다.
  • 이번 주 마감과 다가오는 전형이 대시보드 상단에 뜬다.
  • 카드 안에서 준비물을 체크한다. 이력서 버전, 문항별 자소서 상태, 성적증명, 자격증, 어학, 경험기술서.
  • 같은 회사에 여러 번 지원해도 기업 분석은 한 번만 쌓인다.
핵심 기능
  • 칸반 보드 + 캘린더 뷰 + D-day 목록
  • 지원 카드: 준비물 체크리스트, 자소서 문항 목록(M5 초안으로 연결), 제출한 문서 버전 고정
  • 기업 프로필: 인재상, 핵심가치, 기술 스택, 채용 프로세스, 내가 모은 면접 질문, 최근 뉴스 메모
  • 노션 CSV 임포트(첫날 만들 것). 기존 페이지의 필드를 그대로 매핑
데이터

Company, JobPosting, Application(status, deadline, result), Requirement(checklist), EssayQuestion, EssayDraft → Document

AI
  • 공고 텍스트 → 구조화 추출. 스키마를 고정한 구조화 출력으로 처리해서 파싱 실패를 없앤다.
  • 기업 분석 초안: 웹 검색 도구로 인재상·최근 이슈를 모아 요약. 사람이 확인 후 저장.
  • 문항별 "내 경험 중 쓸 만한 것" 매칭 제안(M1 경험 뱅크 조회).
MVP 경계

포함: 칸반, 카드, 체크리스트, URL 추출, 노션 임포트, 기업 프로필 수동 입력.
이후: 기업 분석 자동화, 알림(이메일·카카오), 채용 사이트 자동 수집.

리스크
  • 채용 사이트 크롤링은 약관·차단 문제가 있다. 붙여넣기 방식으로 시작하고 자동 수집은 공식 API가 있는 곳만.
  • 노션 병행 기간에 데이터가 갈라진다. 임포트를 2회 이상 멱등하게 돌릴 수 있게 만든다.
M1

프로젝트 · 경험 뱅크

Phase 0컨텍스트의 원천공개 가능
목적

프로젝트 하나를 열면 무엇을 하는 서비스인지, 어떤 기술을 썼는지, 내가 무엇을 했는지, 무엇이 문제였고 어떻게 풀었는지, 무엇이 남았는지가 항목별로 보인다. 그리고 그 내용을 STAR 단위의 "경험"으로 쪼개서 이력서·자소서·면접에서 재사용한다.

유저 스토리
  • 프로젝트 카드를 만들고 섹션을 채운다. 개요(한 줄, 기간, 팀 규모, 내 역할), 기능 목록, 기술 스택(언어·프레임워크·인프라·도구), 아키텍처 도식, 성과 지표(수치), 트러블슈팅, 개선점·미해결, 링크(레포·배포·PR).
  • GitHub 레포를 연결하면 PR 목록이 동기화되고, PR마다 요약과 "경험 후보"가 제안된다. 승인하면 경험 뱅크에 들어간다.
  • 경험 하나를 열면 어느 자소서, 어느 면접 답변에 썼는지 사용 이력이 보인다.
핵심 기능
  • 프로젝트 카드 편집기(섹션 템플릿 고정)
  • 경험(Experience) CRUD: 상황·과제·행동·결과 + 역량 태그(문제해결, 성능, 장애 대응, 협업, 설계) + 근거 링크
  • GitHub 동기화: PR 제목·본문·diff 요약 → 경험 후보
  • "면접관 시선" 점검: 프로젝트 설명을 읽고 면접관이 물을 법한 질문 5개를 뽑아 빈칸을 드러냄
데이터

Project, ProjectSection(type, body), TechStackItem, Metric, Experience(S,T,A,R, tags, evidence[], usages[]), PullRequestSummary

AI
  • PR 요약과 경험 후보 추출(배치 처리 가능)
  • 프로젝트 설명 다듬기와 개선점 제안
  • 경험 태깅 자동화
MVP 경계

포함: 수동 프로젝트 카드, 경험 CRUD, 태그.

M2

지식 노트 · 퀴즈

Phase 3공용 학습 엔진기술블로그로 공개
목적

배운 것을 기록하고, 잊기 전에 다시 꺼내게 만들고, 그 내용을 면접 답변으로 이어준다. 기술블로그와 CS 복습을 하나의 노트 시스템으로 묶는다.

유저 스토리
  • 개념 노트, 트러블슈팅 노트(상황·원인·해결·배운 점·재발 방지 템플릿), 회고 노트를 마크다운으로 쓴다.
  • "이 노트로 문제 내줘"를 누르면 객관식·단답·서술·꼬리질문이 생성되고 바로 푼다. 내 답이 채점되고 근거와 함께 피드백이 온다.
  • 오늘의 복습 목록에 틀린 문제와 기한이 된 문제가 올라온다.
  • "다음에 뭐 공부하지"를 누르면 내 노트의 빈 곳과 지원 기업 스택을 기준으로 주제가 제안된다.
  • 노트를 공개로 바꾸면 블로그 URL이 생긴다.
핵심 기능
  • 마크다운 편집기, 코드 블록, 태그 트리(네트워크·OS·DB·자료구조·Spring·JPA·인프라)
  • 퀴즈 생성 → 풀이 → 채점 → 오답 → 간격 반복(SRS) 큐. 이 엔진을 M3·M4·M6이 공유
  • 노트 ↔ 프로젝트 ↔ 경험 연결(트러블슈팅은 곧 면접 소재)
  • 공개 노트 목록 페이지(M7 블로그 탭)
데이터

Note(type, body, tags, visibility), Question(source, type, rubric, answerKey), Attempt(answer, score, feedback), ReviewSchedule(nextDueAt, interval)

AI
  • 문제 생성은 배치로 미리 만들어 두고(대량은 Batch API로 비용 절감), 풀 때는 채점만 호출
  • 서술형 채점은 루브릭을 함께 주고 점수와 누락 키워드를 구조화 출력으로 받는다
  • 노트 → 예상 면접 질문 변환(M6 질문 뱅크로 전송)

  • 노트가 쌓이지 않으면 퀴즈도 없다. 트러블슈팅 템플릿을 프로젝트 화면에서 바로 열 수 있게 진입 장벽을 낮춘다.

핵심 기능

  • 항목별 노트(M2)와 문제(M2 엔진, 유형만 다름)
  • 스피킹은 M6 세션을 영어 질문·제한시간·녹음 모드로 실행

M4

코딩테스트

Phase 3활동 잔디 공개
목적

푼 문제를 기록해서 약점을 보고, 틀린 문제를 다시 풀게 만들고, 지원 기업의 코테 유형에 맞춰 준비한다.

유저 스토리
  • 문제 링크와 결과, 걸린 시간, 막힌 지점, 참고 여부, 내 코드를 남긴다. 문제 본문은 저장하지 않는다.
  • 유형별 정답률·시간 히트맵과 스트릭이 보인다.
  • 틀렸거나 참고한 문제가 3일·7일·30일 뒤 재풀이 큐에 올라온다.
  • 지원 기업을 고르면 그 회사 코테 유형에 맞는 추천 세트가 나온다.
  • 내 코드를 붙이면 시간복잡도, 엣지 케이스, 더 나은 접근을 리뷰받는다. 정답 코드는 주지 않고 단계별 힌트만.
핵심 기능
  • 문제·시도 기록, 유형 태그(구현·그래프·DP·문자열·시뮬레이션·SQL 등)
  • 대시보드: 히트맵, 스트릭, 재풀이 큐(M2 엔진의 ReviewSchedule 재사용)
  • 기업별 유형 매핑. 예: 삼성 SW역량테스트는 구현·BFS·시뮬레이션, 카카오는 구현·문자열·자료구조, 금융권 필기는 기본 알고리즘과 SQL
  • SQL 문제 생성(SQLD 지식 유지 겸용)
데이터

Problem(platform, externalId, url, difficulty, tags), Attempt(durationSec, result, code, stuckAt, referenced), CompanyTestProfile(types[])

AI
  • 코드 리뷰와 단계별 힌트
  • 유사 문제·다음 문제 추천
  • 시도 메모 → 유형 태그 자동 분류

M5

이력서 · 포트폴리오 · 자소서 버전관리

Phase 1git 모델현재 버전만 공개
목적

마스터 문서 하나에서 기업별 파생본을 만들고, 무엇을 어디에 냈는지 추적하고, 언제든 되돌린다. 자소서는 문항별로 근거 경험과 함께 버전을 남긴다.

모델

git과 같은 구조로 설명 가능하게 만듭니다. 그 자체가 면접 소재입니다.

  • Document: 이력서, 포트폴리오, 자소서(지원 단위)
  • Branch: 마스터, 그리고 기업별 브랜치
  • Version: 불변 스냅샷 + 메시지 + 시각. 되돌리기는 새 버전 생성
  • Block: 섹션 단위(인적사항·기술·프로젝트·경험·자격증·수상). 블록은 M1의 프로젝트·경험을 참조하고, 원본이 바뀌면 반영 여부를 묻는다
유저 스토리
  • 마스터 이력서를 편집하고 "커밋"한다. 버전 목록에서 두 버전을 골라 diff를 본다.
  • 지원 카드에서 "이 회사용 브랜치 만들기"를 누르면 마스터에서 갈라진 이력서가 생긴다.
  • 제출 버튼을 누르면 해당 버전이 지원 카드에 고정되고 잠긴다.
  • 자소서 문항마다 글자 수 제한 안에서 초안을 만들고 다듬는다. 각 문단에 근거 경험이 링크된다.
  • PDF로 내보내고, 공개 프로필에 노출할 버전을 고른다.
핵심 기능
  • 블록 편집기, 버전 저장, diff 뷰, 브랜치 생성, 복원, 제출 잠금
  • 자소서 문항 초안, 글자 수 카운터, 근거 경험 링크
  • PDF 내보내기(템플릿 1~2종이면 충분)
데이터

Document(type), Branch(name, companyId?), Version(snapshot JSONB, message, createdAt, locked), Block(type, body, refs[]), EssayDraft(questionId, versionId, evidence[])

AI
  • 문항 초안 생성. 반드시 경험 뱅크의 항목을 인용하고, 인용 없는 문장은 표시한다
  • 글자 수 맞춤 축약·확장, 기업 인재상 대비 톤 점검
  • JD 요구 역량 대비 갭 리포트("이 공고는 대용량 처리 경험을 요구하는데 근거가 없다")
MVP 경계

포함: 문서·버전·브랜치·diff, 자소서 초안.
이후: PDF 템플릿, 갭 리포트, 원본 변경 전파.

리스크
  • AI 초안을 그대로 내는 유혹. 생성본은 "초안" 상태에서 제출 버튼이 비활성화되고, 한 번 이상 수동 편집해야 확정된다.
  • 버전이 너무 많아진다. 자동 저장은 임시본으로만 두고 커밋은 명시적으로.
M6

면접 준비 · 모의면접

Phase 2실시간비공개
목적

내 모든 정보와 지원한 기업의 인재상을 바탕으로 예상 질문과 답변을 카테고리별로 쌓고, 제한시간이 있는 실시간 모의면접으로 순발력을 기른다.

질문 뱅크
  • 카테고리: 인성·조직 적합, 기술(CS), 프로젝트 심층, 기업별, 상황·케이스, 영어
  • 출처: 자동 생성, 수집한 기출, 직접 추가
  • 질문마다 답변 초안, 근거 경험 링크, 핵심 키워드, 예상 꼬리질문
  • 자동 생성 입력: 현재 이력서 버전 + 프로젝트 카드 + 지원 기업의 인재상·공고. 출력: 예상 질문 30개와 꼬리질문
모의면접 세션
  • 설정: 대상(지원한 기업 중 선택, 또는 일반), 카테고리 비율, 문항 수, 질문당 제한시간(60~120초)
  • 진행: 질문 표시 → 타이머 → 음성으로 답변(전사) → 답변 내용에 따라 꼬리질문이 스트리밍으로 이어짐 → 다음 문항
  • 리포트: 문항별 전사, 두괄식 여부, 구체성(수치·근거 유무), 시간 사용, 키워드 매칭, 말버릇 빈도, 총평. 이전 세션과 비교한 변화
  • 환류: 좋았던 답변은 질문 뱅크의 모범 답안으로 승격
기업별 모드

M0에서 지원한 회사만 선택 가능. 그 회사의 인재상·핵심가치·공고·내가 제출한 자소서를 면접관 페르소나에 넣어서 "그 회사가 물어볼 법한" 질문을 만든다. 금융권과 공기업은 인성·직무 적합 비중을 높이고, 서비스 기업은 프로젝트 심층 비중을 높이는 프리셋을 둔다.

데이터

InterviewQuestion(category, source, companyId?, answerDraft, evidence[], followUps[]), InterviewSession(config, companyId?), SessionTurn(question, transcript, durationSec, evaluation JSONB)

AI · 기술
  • 질문 생성과 리포트는 일반 호출, 꼬리질문은 스트리밍
  • 세션 동안 프로필·기업 컨텍스트는 시스템 프롬프트 앞부분에 고정해 프롬프트 캐싱을 태운다
  • 음성: 1단계 브라우저 Web Speech API, 2단계 서버 STT. 질문 읽어주기(TTS)는 옵션
  • 실시간 연결: 세션당 WebSocket 하나, 타이머는 서버가 권위
MVP 경계

포함: 질문 뱅크 + 텍스트 입력 모의면접 + 리포트.
2단계: 음성 입력. 3단계: 실시간 꼬리질문, 기업별 프리셋, 세션 간 비교.

리스크
  • 피드백이 뻔해진다. 루브릭을 명시하고, 항상 "이 답변에서 빠진 근거"를 M1 경험 뱅크에서 찾아 제시한다.
  • 브라우저 STT는 한국어 인식률이 들쭉날쭉하다. 전사 편집 기능을 두고 정확도가 문제되면 서버 STT로 교체.
M7

공개 프로필

Phase 1 (라이트)증빙이 붙은 이력서
목적

링크 하나로 "이 사람"을 보여준다. 자소서 링크란, 이력서 하단, GitHub 프로필에 붙이는 URL. 코드·글·자격증·활동 데이터가 붙어 있어 이력서의 문장이 증빙으로 이어진다. 그리고 이 사이트 자체가 "직접 설계하고 구현했다"는 증빙이 된다.

구성
  • 상단 요약: 한 줄 소개, 기술 스택, 연락처(선택), GitHub·블로그 링크
  • 프로젝트: M1에서 공개로 표시한 카드. 기능·스택·역할·성과·트러블슈팅 요약
  • 기술 노트: M2 공개 노트 목록(블로그)
  • 자격증: M3 취득분과 취득일
  • 활동: M4 문제 풀이 잔디, M2 복습 통계. "꾸준함"의 증빙
  • 이력서: M5에서 공개로 지정한 현재 버전 1개, PDF 다운로드
  • 이 사이트에 대하여: 아키텍처, 스택, 만든 과정. 프로젝트 카드 중 하나로 자동 포함
원칙
  • 모든 엔티티에 visibility. 기본 비공개. 지원 현황·기업 분석·면접 기록·자소서는 공개 옵션 자체가 없음
  • 로그인 없이 읽기 전용. SSR 또는 정적 생성으로 첫 화면 1초 내
  • 개인정보 최소화: 학번·전화·생년 노출 금지, 연락은 이메일 또는 폼
  • OG 이미지와 메타 태그로 링크 미리보기가 깔끔하게 뜨게
  • 본인 이름 도메인 사용
MVP 경계

라이트(Phase 1): 프로젝트 카드 + 자격증 + 현재 이력서. 공채 자소서 링크란에 넣을 수 있는 최소 형태.
정식(Phase 4): 블로그 탭, 활동 그래프, OG 이미지, 커스텀 도메인, 조회 로그.

리스크
  • 공개 범위 실수. 공개 페이지는 별도 읽기 모델(뷰 전용 쿼리)만 사용하고, 비공개 엔티티는 그 모델에 애초에 존재하지 않게 한다.
  • 내용이 비어 보이면 역효과. 프로젝트 2개, 노트 5개 이상 채워진 뒤에 링크를 배포한다.

4. AI 통합과 MCP

"MCP를 달아야 하나"에 대한 답
결론

실시간 처리와 MCP는 별개의 문제입니다. 웹앱 안의 AI 기능은 서버가 Claude API를 직접 호출하고, 필요한 데이터는 도구 호출로 내 DB에서 읽으면 됩니다. MCP는 MVP에 필요 없습니다. MCP가 가치 있는 지점은 따로 있고, 그건 Phase 4에 얇게 붙입니다.

MCP는 무엇이고 언제 필요한가

  • MCP(Model Context Protocol)는 도구와 데이터를 LLM 클라이언트(Claude Desktop, Claude Code 등)에 노출하는 표준입니다. 내 서버가 "제공자"가 되고, 외부 에이전트가 "소비자"가 됩니다.
  • 우리 웹앱은 반대 방향입니다. 우리 서버가 Claude API의 소비자이고, 데이터는 이미 우리 DB에 있습니다. 여기에 MCP를 끼우면 계층만 하나 늘어납니다.
  • MCP가 빛나는 경우: 내가 Claude Code나 Claude Desktop에서 "OO 자소서 초안 잡아줘"라고 말했을 때, 그 에이전트가 내 프로젝트·경험·지원 정보를 직접 읽게 하고 싶을 때. 즉 내 컨텍스트를 어떤 도구에서든 쓰게 하는 것입니다.
  • 구현은 서비스 레이어 위에 REST 어댑터와 MCP 어댑터를 나란히 두는 것입니다. 읽기 도구 위주로 시작합니다: 프로필 조회, 경험 검색, 지원 목록, 기업 프로필. 이 구조 자체가 "포트와 어댑터" 설명이 되어 면접 소재가 됩니다.

실시간은 이렇게

  • 모의면접의 꼬리질문은 Claude API 스트리밍을 받아 WebSocket으로 브라우저에 흘려보냅니다.
  • 타이머는 서버가 관리하고 브라우저는 표시만 합니다. 새로고침해도 세션이 이어집니다.
  • 음성 전사는 브라우저에서 하고, 텍스트만 서버로 보냅니다. 오디오 저장은 하지 않아 개인정보 부담을 줄입니다.

AI 게이트웨이 설계

구성요소역할메모
컨텍스트 조립기작업별로 필요한 것만 모아 프롬프트를 만든다. 프로필 요약 + 관련 경험 상위 몇 개 + 기업 프로필초기엔 데이터가 작아 검색 없이 구조화 조립으로 충분. 경험이 100개를 넘으면 pgvector로 검색
프롬프트 템플릿작업 유형별 템플릿을 파일로 관리하고 버전을 남긴다템플릿 변경이 품질에 미친 영향을 호출 로그로 비교
구조화 출력추출·채점·리포트는 JSON 스키마를 고정파싱 실패와 필드 누락을 없앤다
프롬프트 캐싱프로필·기업 컨텍스트를 시스템 프롬프트 앞에 고정 배치모의면접처럼 한 세션에 여러 번 호출할 때 입력 비용이 크게 준다
호출 로그입력·출력·토큰·비용·내 평가(좋아요/별로)를 남긴다나중에 프롬프트 개선 근거. 비용 대시보드도 여기서
초안 게이트모든 생성물은 draft 상태로 저장, 확정은 사람이M5 제출 잠금, M3 사실 확인 체크와 연결

5. 로드맵

하반기 공채 일정에 맞춘 순서 · 각 단계는 끝나는 즉시 실사용

하반기 공채는 대체로 9~10월 서류, 10~11월 필기·코테, 11~12월 면접으로 흐릅니다. 모듈 순서는 이 흐름을 따릅니다. 학습 계열(M2·M3·M4)은 겨울 시험을 겨냥해 뒤에 둡니다.

Phase 0
9월 2~3주

뼈대 + 지원 파이프라인 + 경험 뱅크

완료 기준: 노션을 열지 않아도 공고 관리가 된다.

  • 프로젝트 골격, 인증, 도메인 모듈 경계, DB 스키마
  • M0: 칸반·카드·체크리스트·URL 추출·노션 CSV 임포트
  • M1: 프로젝트 카드, 경험 CRUD
  • AI 게이트웨이 최소형: 템플릿 1개, 구조화 출력, 호출 로그
Phase 1
10월

문서 버전관리 + 자소서 초안 + 공개 프로필 라이트

완료 기준: 실제 공채 자소서 1건을 이 시스템에서 써서 제출하고, 링크란에 프로필 URL을 넣는다.

  • M5: 문서·버전·브랜치·diff, 문항 초안, 제출 잠금
  • M7 라이트: 프로젝트 카드 + 자격증 + 이력서 공개 페이지, 본인 도메인

10~11월

질문 뱅크 + 모의면접

  • M6: 질문 뱅크, 자동 생성, 텍스트 모의면접, 리포트
  • M6 2단계: 음성 입력, 스트리밍 꼬리질문

11~12월

학습 엔진 + 자격증 + 코테

완료 기준: 정보처리기사 실기와 다음 자격증 준비를 이 시스템에서 한다.

  • M2: 노트, 퀴즈 생성·채점, 복습 큐
  • M3: 트랙·일정·출제기준, M2 엔진 재사용
  • M4: 기록·대시보드·AI 리뷰
Phase 4
2027년 초

연동과 확장

완료 기준: Claude Code에서 내 컨텍스트를 바로 읽어 초안을 만든다.

  • GitHub PR 동기화, MCP 서버(읽기 도구), 알림, 공개 프로필 정식(블로그·활동 그래프·OG)
  • pgvector 경험 검색, 스피킹 모드
